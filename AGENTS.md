- Marketing tracking goes through `trackEvent` in src/lib/analytics.ts into the `marketing_events` table (consent-gated, no personal data); leads carry first-touch UTM attribution — keeps funnel data first-party and joinable with leads.
- Admin users are created via the admin-only `admin-users` edge function — never by writing to auth tables directly (that broke logins before).
- CRM ownership uses protected role-validated user IDs; editors read only the team directory while account creation remains admin-only.
- CRM tasks, campaign mappings and lead audit history are persisted separately from consent-gated marketing events; lead service attribution is explicit so rejected tracking consent never hides a customer from sales.
- Reporting paginates database and advertising reads; funnels require ordered same-service events, paid attribution requires paid media, and sales use closing dates and explicit values rather than inferred clicks.
- Sales operations keep interactions and offers separate from leads; duplicate emails reveal related history without destructive merging, and accepted offers never silently book revenue.
- CRM assignment notifications are generated transactionally for role-validated recipients; upcoming and overdue reminders are derived in the daily workspace rather than persisted by polling jobs.
- Customer receipt emails are sent only after lead persistence; delivery failures must not turn a saved submission into a failed submission.
- Scheduled CRM emails use single-use, short-lived run capabilities in service-only writable run tables; manual previews and sends require server-validated admin sessions to prevent public email triggers.
- A single daily schedule dispatches overdue mail and the weekly digest at Helsinki local time; contact evidence and calendar windows are derived, and ad-spend reads are shared with the existing reporting function to prevent metric drift.
- Sales goals are admin-managed per service and Helsinki calendar month; actual revenue uses explicit closing dates and values, with missing values disclosed, so target attainment never implies inferred sales.
- New unowned leads are assigned by a database BEFORE INSERT trigger with a locked per-rule round-robin cursor and live role validation; explicit service rules override the site default, including disabled rules, and existing owners are never overwritten.
- The admin home is a read-only operations center; the existing content editor lives at /admin/sisallot so CRM and public functionality remain independent.
- Operations metrics and their URL-addressable queues share operationsCenter calculations and paginated reads, so linked rows use identical service, owner and time boundaries.
- Public booking and coaching panels mount only outside admin routes, preventing offscreen dialogs and shadows from interfering with the workspace.
- M1 registration links and explicit Helsinki-calendar deadlines live in the course data; the local participant form stays behind a registration-channel flag, and outbound clicks never count as completed registrations because Lyyti owns confirmation.
- AI Talent Hub access is decided by email-matched, confirmed-account rows in ai_talent_members (site admins also manage it); the page is gated by AI_TALENT_PUBLISHED so production stays hidden until approval.
